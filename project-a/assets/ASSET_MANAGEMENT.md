# 美术素材管理方案

> 适用范围：`project-a/` 内所有第三方、自制、委托及 AI 生成的视觉素材
> 目标：来源可追溯、许可可发布、导入可复现、替换不破坏、Web 包体可量化
> 更新日期：2026-07-31

## 1. 单一事实源

- `assets/asset_manifest.md`：视觉素材批次、来源、许可、文件哈希、用途和验证状态；
- `assets/licenses/`：必须随项目保存的许可证或来源声明；
- `design/art/asset-requirements.md`：需求、优先级、技术规格和验收场景；
- Godot 源文件与对应 `.import`：当前真实导入配置；
- `artifacts/`：运行截图证据，不作为素材源文件。

素材存在于目录中不代表可以使用。只有 manifest 状态为 `approved`，且许可证、哈希和代表性导入检查完整的素材，才可进入发布场景。

## 2. 来源状态

每个素材批次使用以下状态之一：

| 状态 | 含义 | 是否可进发布 |
|---|---|---|
| `candidate` | 已找到官方页，尚未完成许可或内容检查 | 否 |
| `staged` | 已安全下载到临时目录并检查，尚未导入 | 否 |
| `approved` | 许可、文件、哈希、导入与用途均已验证 | 是 |
| `restricted` | 仅原型可用、需署名或存在额外限制 | 默认否 |
| `blocked` | 来源、许可或内容冲突 | 否 |
| `retired` | 已替换且引用清理完成，仅保留记录 | 否 |

## 3. 目录与所有权

```text
assets/
├── ui/icons/<pack_id>/              # UI 图标源文件
├── 3d/environment/<pack_id>/        # 第三方环境模型
├── 3d/<project_owned_kit>/          # 项目专属角色/模型批次
├── textures/environment/<pack_id>/  # 环境纹理
├── fonts/
├── licenses/
├── asset_manifest.md
└── ASSET_MANAGEMENT.md
```

- 第三方下载素材不得放入平台保留的 `assets/generated/` 或 `assets/uploads/`；
- 源素材放在 `assets/`，功能包装场景放在 `game/scenes/<owner>/`；
- 只有跨多个界面/场景复用的素材才进入共享目录；
- 压缩包、下载临时文件和未选中的源包内容不得提交；
- `.godot/imported/` 是生成缓存，不手工编辑、不作为来源证据。

## 4. 命名

- 目录与文件统一 `lowercase_snake_case`；
- 第三方批次目录使用稳定 `pack_id`，不使用“new”“final”等时间性命名；
- 语义包装资源使用游戏内名字，如 `icon_energy.png`、`urban_barrier_a.tscn`；
- 原始文件重命名后在 manifest 记录原文件名；
- 若 glTF/GLB 通过相对 URI 硬编码上游目录名（如 `Textures/`），为保证可重导入可保留该
  依赖目录的原始大小写，并在 manifest 记录例外；
- Web 路径大小写敏感；任何改名都必须搜索全部 `res://` 引用。

## 5. 引入流程

### 5.1 需求确认

先在素材需求文档中确认用途、运行尺寸、格式、风格、许可和性能预算。没有明确使用位置的包不下载。

### 5.2 官方来源与许可

1. 只访问 source registry 允许的官方域名；
2. 打开准确的资产页，不使用镜像、转载或搜索结果缓存；
3. 同时核对资产页、站点许可说明和包内许可证；
4. 记录商业使用、修改、署名、再分发和商标限制；
5. 任一信息未知或冲突时标记 `blocked`，不导入。

### 5.3 安全暂存

1. 下载到系统临时目录；
2. 验证响应类型与合理大小；
3. 解压前列出条目，拒绝绝对路径、`..`、链接、设备文件和重复归一化路径；
4. 不执行包内脚本、安装器、宏或编辑器插件；
5. 只复制需求清单内的最小子集。

### 5.4 导入与包装

- UI：优先透明 PNG；在 20、24、32 px 检查剪影、透明边和过滤；
- 3D：优先 GLB/glTF；通过独立 `.tscn` 包装缩放、轴向、材质和碰撞；
- 纹理：3D 缩放纹理启用 mipmap；移动 Web 默认不超过 2048，除非测量证明需要；
- 不直接修改第三方 GLB 内部导入节点来承载玩法逻辑；
- 固定依赖使用 `preload()`；数据驱动路径必须用稳定 ID allowlist。

### 5.5 记录

每个批次至少记录：

- `pack_id`、名称、作者、官方资产页、下载日期；
- 许可名称、官方许可 URL、包内许可文件和署名文本；
- 商业使用/修改/再分发状态；
- 选取与舍弃的内容、项目用途和修改；
- 每个保留源文件的 SHA-256；
- Godot 版本、导入结果、代表场景与 Web 验证；
- 文件总大小及相对上一版的 Web `.pck` 增量。

### 5.6 生成式 UI 美术工作流

生成式位图只负责气氛、材质和世界观，不生成按钮、文字、图标或玩法信息。可交互内容仍由
Godot Control 节点和共享 `ui_art_direction.gd` 承载，确保可读性、响应式布局与焦点状态一致。

1. **锁定视觉母题**：先写清既有色板、材质、光向、透视、题材禁区，以及 UI 需要占用的
   安静留白区域；提示词必须要求“无文字、无标志、无水印、无现成作品角色”。
2. **只生成一个明确用途**：按真实界面宽高比生成背景或装饰层，不把多张候选和原始大图
   一并放进仓库。
3. **裁切后再压缩**：裁到目标运行尺寸；不需要透明通道的背景优先 WebP。默认单张背景
   目标 ≤ 128 KiB，细节以 568×320 仍能支撑气氛、但不干扰文字为准。
4. **在真实 UI 中审查**：必须叠加最终面板、按钮和中文文本，分别检查 844×390 与
   568×320；禁止只看裸图判断完成。
5. **统一性门禁**：逐项对照共享深色工业底、瓷白主体、青色状态、金色主行动语义；若新增
   颜色或材质不能在现有系统中解释，则退回重做。
6. **记录与回归**：manifest 记录生成方式、提示词摘要、变换、哈希、源图是否保留、最终
   体积和代表截图；运行导入、相关 UI 测试与人工视觉审查后才标记 `approved`。

## 6. 许可文件

- 可保存官方纯文本许可时，放入 `assets/licenses/<pack_id>_<license>.txt`；
- 许可证不要求随包分发时，也要在 manifest 保存官方 URL 和核验日期；
- 署名要求同步到 `release/LICENSES.md`；
- CC0 也必须记录来源和作者，不能用“免版权”代替准确许可名称；
- 商标、人物肖像和已知 IP 风险独立记录，版权许可不自动解决商标问题。

## 7. 哈希与变更

- SHA-256 对当前提交中的源文件计算；
- 裁切、重命名、转格式、压缩、重着色都要记录；
- 同名目标已存在时先比哈希：相同则复用，不同则使用新名字并审查引用；
- 禁止静默覆盖；
- 上游包更新视为新版本批次，重新检查许可、哈希、导入和画面。

## 8. 验证门禁

视觉素材合入前至少完成：

1. `godot --headless --path project-a --editor --quit` 无导入错误；
2. 相关 UI smoke/场景测试通过；
3. 844×390 代表画面人工检查；
4. 图标在最小运行尺寸与灰度下可区分；
5. 3D 资产在 Compatibility 渲染下检查轴向、比例、材质、透明、动画和碰撞；
6. Web 导出成功，记录 `.pck` 体积增量；
7. `git diff --check` 与文档 lint 通过；
8. manifest、license 与 `release/LICENSES.md`（如需署名）同步。

## 9. 性能预算

| 类别 | 默认预算 |
|---|---|
| UI 图标源图 | 单图建议 ≤ 128 KiB；运行显示 20–32 px |
| 单张环境纹理 | 默认 512–1024；无测量不超过 2048 |
| 单个常规环境道具 | 建议 ≤ 10k 三角面 |
| 单个英雄主模型 | 记录实际面数；移动 Web 以同屏峰值测量为准 |
| 新增环境批次 | 首轮只保留代表性最小子集 |
| 初始 Web 包体 | 每批次必须记录增量，不以磁盘源文件大小代替 |

预算是预警线，不是质量证明；超过预算必须给出截图/性能数据和保留理由。

## 10. 替换与退役

1. 找到所有 `res://` 引用和包装场景；
2. 引入新资产并行验证，不原地覆盖；
3. 更新场景、manifest、许可和截图；
4. 验证导入、测试、Web 构建；
5. 删除旧源文件并让 Godot 正常清理导入状态；
6. 将旧 manifest 条目标记为 `retired`，保留历史来源和替换提交。

## 11. 提交检查表

- [ ] 需求文档存在对应条目；
- [ ] 官方来源与许可证已核验；
- [ ] 只保留最小使用子集；
- [ ] 路径和名称符合规范；
- [ ] manifest 含 SHA-256 与用途；
- [ ] 必要许可文本已保存；
- [ ] Godot 导入和代表场景已验证；
- [ ] Web 包体增量已记录；
- [ ] 没有压缩包、临时文件、未知来源素材或无关用户改动进入提交。
