# UX / Visual Spec：马桶人工厂 SLG 界面刷新

> 状态：已实现第二轮玩家化重构，等待真人触屏复核
> 平台：Godot 4.6.3 / Web / 手机横屏 844×390
> 输入：触屏优先，兼容鼠标与键盘焦点

## 第二轮方向：从交付仪表盘回到游戏世界

第一轮解决了可读性，但仍把大量系统说明、推荐战力、资源效率和操作步骤常驻在首屏，
更像供开发者验收的控制台。第二轮改为：

- UI 使用战报、无线电、侦察影像、出击名单和地下工厂等世界内语汇；
- 每屏只保留一个主行动，系统解释进入档案、详情或设置；
- 标题页先建立 Gman 与失守地表的剧情，不展示完整账号仪表盘；
- 基地用“前线来电”承载当前行动，建造步骤与库存移到下方滚动区；
- 战区首层让路线与五个当前城镇节点保持可见，并用右下情境卡同屏显示推荐战力、能力比、
  风险与唯一主行动；不再设置独立战前会议或二次确认页；
- 战斗 HUD 采用线上移动战术游戏常见的边缘锚定：阶段/即时威胁放在左上信息岛，暂停与
  自动模式放在右上，角色生命和能量卡仅按实际出战人数包裹在底部，不再用上下通栏压住战场；
- 军团首层只显示阵型和成员，招募概率、角色成长明细继续留在下层；
- 顶栏移除常驻指挥等级，设置收敛为单个菜单入口；
- 导航使用“工厂 / 战区 / 军团 / 行动”，奖励数量表达为待确认战报，不使用红点劳动语气。

视觉命题调整为：

> 被战火唤醒的地下工厂：焦黑金属承载面、暖橙警戒光、冷青机械回应，
> 平时克制，只有出击、危险和重大收获提升亮度。

## 玩家目标

玩家进入任一界面后，应在两秒内回答两个问题：

1. 当前战争局势发生了什么；
2. 我现在最自然的行动是什么。

成本、收益和详细限制只在玩家准备提交不可逆动作时出现，不提前占据首屏。

## 视觉命题

低模战争玩具工厂 + 深色机械控制台 + 克制的战术荧光。

- 深蓝黑：稳定信息与承载面；
- 青色：当前选择和可立即执行的主行动；
- 金色：资源、收益和成长机会；
- 红色：高战损、失能和不可忽略的风险；
- 绿色：完成、占领和安全战备。

颜色不能单独承担状态。选择同时使用描边与位置，风险同时使用文字，禁用同时降低明度并锁定输入。

## 核心布局

### 线上参考原则

布局参考《明日方舟》战斗界面的成熟做法：把波次、生命、速度与暂停固定在屏幕边缘，让
战术地图持续占据主体；可部署角色和技能只在需要操作的边缘区域出现。项目只采用“中央留空、
边缘锚定、即时危险覆盖常规状态”三条信息架构原则，不复制角色、美术、图标或具体构图。
参考入口为其官方 Google Play 产品页与游戏截图：
`https://play.google.com/store/apps/details?id=com.YoStarEN.Arknights`。

### 工厂

工厂采用 Supercell 官方《Clash of Clans》Builder Base 所体现的基地交互原则：基地世界本身是
主操作面，资源退到边缘，选中建筑后才出现情境动作，建造/编辑是可明确退出的临时模式。项目
仅采用这些层级原则，不复制建筑造型、图标、配色或具体构图。参考入口：
`https://supercell.com/en/games/clashofclans/blog/news/actual-welcome-to-the-builder-base/`。

```text
标题 / 当前语境
┌─ 后勤短岛 ─┐       3D 工厂岛        ┌─ 当前行动 ─┐
│资源 / 收取 │ 建筑轮廓、名称、等级  │ 唯一主动作 │
└────────────┘ 点击建筑；地块青色高亮 └────────────┘
                       四入口底部导航
```

首屏至少 75% 内容区域保留给可旋转、缩放、点击的工厂世界；后勤与情境卡是互不相交的贴边
信息岛，不再形成顶栏或右侧通栏。当前行动优先于完整库存。进入建造放置后，常规页签隐藏，
仅保留造价、放置提示、确认与取消；资源建筑的领取结果必须报告实际入库量与溢出量，升级前
必须展示金币、工业技术和可感知收益。

### 战区

五张长文卡改为：

1. 章节选择；
2. 五个直接落在战术路线上的可点击城镇节点，不再使用独立按钮条；
3. 单个选中城镇详情；工厂“前线”动作直接聚焦最高已解锁城镇；
4. 稳定位置的风险标记和进攻按钮。

一次只阅读一份敌情，不在五个节点中重复长文。章节超过五个城镇时，节点条围绕当前选择滑动，
不把整章关卡压成一排按钮；章节/城镇选择使用青色，金色只承担当前主行动和底部所在入口。
Boss 也不展开中央战前会议：标准与紧凑横屏的详情卡高度均不超过 86 px，战力合并进关卡身份，
风险保持一行，培养与试探使用扳手/目标 PNG 图标和短标签；两条完整 2★恢复路线进入卡片 tooltip。
该结构参考 Boom Beach 的“战区地图 → 点选岛屿 → 侦察/进攻”决策层级，而不复制其美术。

### 战斗

1. 左上战况胶囊只显示阶段、当前结构耐久和战线进度；炮击、共振等即时威胁出现时完整替换
   常规战况，避免在固定宽度内追加成长句；
2. 右上只保留暂停与自动/手动模式。撤退属于破坏性操作，实时战斗中隐藏，只在暂停菜单保留；
3. 底部角色 HUD 按出战人数收缩，不绘制全宽承载板。标准横屏保留精确 HP/EN 数字；568
   满编 5–6 人时保留姓名、HP/EN 标签和状态条，隐藏逐卡精确数字，避免缩字或溢出；
4. 角色卡本身仍是手动技能热区，保持至少 48 px 高度和键盘焦点，不在战场中央新增按钮。

### 战术档案

玩法说明不使用编号目录和整页教程文字。四个主题以 2×2 图标卡表达“行动 / 恢复 / 操作 / 数据”，
右侧只保留一句当前原则与三张图标步骤卡；完整说明、隐私语义和版本信息仍存在于 tooltip 与隐藏的
可访问文本。844×390 与 568×320 都必须在首屏同时看到四个主题、三步流程和返回动作。
图标继续复用同一 Kenney PNG 集，避免为二级页面引入另一套视觉语言。

### 军团

军团采用 Supercell 官方《Squad Busters》对出击编成的两条原则：起始阵容围绕明确的 Hero 与
少量成员建立；职业/职责用于帮助玩家理解成员在战斗中的作用。项目仅采用“角色形象优先、
阵位关系直接可点、职责按需出现”的结构，不复制角色、美术或具体卡面。参考入口：
`https://support.supercell.com/squad-busters/en/articles/prepare-your-squad.html` 与
`https://support.supercell.com/squad-busters/en/articles/battles-in-squad-busters.html`。

默认阵型不再使用六个等权纯文字按钮。首屏固定为 2×3 战术阵位：已部署角色显示轻量徽章、
姓名与职责，空位显示直接部署入口；系统只把第一个推荐补位标成金色主行动，当前页签使用
冷青描边而不争夺主强调。战力与下一目标压缩为一行持续语境，候选比较只在玩家点选阵位后
进入滚动详情。568×320 使用短页签和短目标名，但保留完整阵位语义与至少 48 px 热区。

### 目标与行动

行动页采用 Supercell 官方《Clash Royale》Trophy Road 的信息原则：进度以连续路径、里程碑与
关口表达，奖励附着于路径但不取代推进目标。项目只采用“路线先于清单、关口明确、奖励可预览”
的结构，不复制其角色、图标、配色或具体构图。参考入口：
`https://support.supercell.com/clash-royale/en/articles/trophy-road-5.html`。

行动页首屏固定为“章节据点 → 当前行动 → 当前关口”的战役路线，节点使用 64×64 WebP 工业
徽章，不再用大段文字模拟地图。当前关口旁只保留一枚金色挑战按钮；礼包与庆典奖励压缩为
次级补给横条。页签保持冷青选中态，避免与主行动争夺金色强调。生成源经过 Godot 工具脚本
键色、裁切、缩放和有损 WebP 导出，单枚约 2KB，避免把生成大图带进运行时。

成就子页采用 Supercell 官方《Clash Royale》Card Mastery / Badges 与《Brawl Stars》Records
共同体现的原则：长期目标首先是一组可升级、可展示的徽章；总等级、下一奖励和单项进度保持
同屏，详细条件只在点选后展开。项目只采用“徽章先于列表、完成态可展示、奖励形成成长闭环”
的结构，不复制其徽章造型、品牌配色或具体构图。参考入口：
`https://support.supercell.com/clash-royale/en/articles/card-mastery-4.html`、
`https://support.supercell.com/clash-royale/en/articles/badges-3.html` 与
`https://support.supercell.com/brawl-stars/en/articles/records.html`。

成就首屏以指挥官军衔条作为长期语境，下方使用两列或三列 64 px 栅格奖章卡。卡片只常驻
名称、数值进度和领取状态；已完成、进行中与已领取同时通过描边、明度和文字区分。批量领取
是唯一金色主行动，红色通知数不再承担成就状态本身。

战令子页采用 Supercell 官方《Clash Royale》Pass Royale 与《Brawl Stars》Brawl Pass
共同使用的 reward track 原则：奖励必须依附连续 tier、已领取/当前可领取/未到达状态同时
可见，当前战功与下一批奖励保持同屏。项目是免费学习型战令，仅采用“轨道先于列表、奖励图标
先于名称、当前 tier 可定位”的结构，不复制付费轨、角色、宝箱造型或具体构图。参考入口：
`https://support.supercell.com/clash-royale/en/articles/pass-royale-11.html` 与
`https://support.supercell.com/brawl-stars/en/articles/brawl-pass-quests-7.html`。

30 级战令改为 844 五列、568 四列的纵向奖励跑道；卡片复用金币、工业、补给箱和军团数据
WebP，只显示两位等级、状态符号和数量，完整奖励进入 tooltip。金色只标记当前可领取 tier
与唯一批量领取按钮；已领取降低明度，未到达保持深色。跑道允许纵向滚动，不使用横向滚动。

### 科技蓝图

蓝图屏参考 Wargaming 官方《World of Tanks Blitz》科技树的前置研究关系与已研究/未研究状态
区分，以及 Supercell 官方《Clash of Clans》Hero Equipment 用能力图标直接连接战斗打法的
原则。项目只采用“路径可见、状态不只靠文字、选中能力聚焦”的信息结构，不复制车辆、装备、
图标或具体构图。参考入口：
`https://www.wargaming.net/support/en/products/wotb/article/15406/` 与
`https://supercell.com/en/games/clashofclans/blog/news/introducing-hero-equipment/`。

四个分支使用 64×64 WebP 工业徽章和两字短名；选中分支保持冷青描边。主区固定为“分支核心
→ 可研发设计 → 后续设计”的连接路径，节点用图标、边框和短状态共同表达。选中设计只持续显示
职责、主动能力与三阶成长短标签，完整说明进入提示语义；金色只给予当前研发动作。568×320
隐藏与 App Shell 主导航重复的返回按钮，并保证两个设计节点和研发动作同时留在首屏。

### 战斗结算

战报参考 Supercell 官方《Brawl Stars》战斗结束先突出 Game Highlight、随后展示关键统计的
原则，以及《Clash of Clans》把星级、破坏度与战利品作为结果核心指标的做法。项目只采用
“结果情绪先于日志、关键表现可视化、战利品直接可扫读”的结构，不复制角色、星级造型或具体
构图。参考入口：
`https://support.supercell.com/brawl-stars/en/articles/battle-end-game-highlight.html` 与
`https://supercell.com/en/games/clashofclans/blog/news/clan-wars-explained-part-2-battle-day/`。

结果页使用胜利勋章或破损盾牌先表达胜负；实际增加的金币与军团数据分别形成图标筹码，零收益
不占位。战绩固定为用时、击破、消灭三枚徽章，贡献与关键反制合并成一条“本场高光”。下一步
只保留一条短资格和一枚金色 CTA，安全返回是次级动作。完整复盘、经验与解锁事实仍保留在
语义节点和 tooltip 中，不再作为持续占屏的报告段落。

## 可用性与响应式

- 所有按钮至少保持稳定最小高度，并支持键盘焦点；
- 世界中文不使用小尺寸 `Label3D`，采用投影后的屏幕空间标签；
- 844×390 不使用横向滚动；
- 长列表只允许纵向滚动，底部导航保持稳定；
- 主状态同时使用文字、颜色和描边；
- 中文长文允许换行，资源数字和比率禁止逐字折行；
- 后续真机验收必须覆盖手指遮挡、浏览器安全区和 40% 文本扩展。

## 验收

- 玩家在战区两秒内能指出当前选中城镇、推荐战力、风险和进攻按钮；
- Boss 简报在 844×390 与 568×320 均不遮住任一当前五节点，动作不小于 48 px；
- 工厂首屏能找到当前行动，并能直接点击任一资源建筑；
- 领取一栋建筑后明确看到实际入库，其他建筑生产不被重置；
- 军团首屏至少能浏览三名角色的核心状态；
- 胜利、撤退、失败不只依赖颜色区分；
- 844×390 下资源数字不竖排、主按钮不被裁切、导航始终可见；
