# Genre-driven HUD Layouts

这些范式用于快速建立候选布局，不是必须照抄的模板。始终先以当前项目的核心决策、镜头、输入方式和画面密度验证。

## 类土豆兄弟 / 竞技场幸存者

### 玩家任务

- 持续移动和躲避来自多方向的敌人；
- 判断拾取风险、生命余量、波次剩余时间和成长节奏；
- 战斗中进行低频策略调整，波次间完成高密度构筑决策。

### 布局原则

- 中央及角色周围是最高价值行动区，常驻 UI 只能占安全边缘。
- 波次/时间属于全局节奏，可稳定放在顶部中央；危险阶段通过尺寸、颜色和短动效升级，而不是常驻巨大标题。
- 生命应在短视线迁移内读取。可选屏幕边缘稳定生命簇，或角色附近极简世界血条；不要同时展示两套同等强度的信息。
- 经验/波次进度适合细长边缘条，不能形成遮挡敌人的厚底座。
- 材料、等级、击杀等成长信息组成一个次级信息簇，位置固定并弱于生命与计时。
- 武器/被动槽只展示会影响战斗判断的状态。若武器完全自动且没有即时冷却决策，战斗中只保留构筑摘要，完整属性留到波次间。
- 升级、商店、属性比较使用明确的阶段切换界面；不要在仍需躲避敌人时弹出复杂卡片。
- 拾取反馈从世界物体向资源计数归位，高频拾取应合并，不逐条弹通知。

### 突出游戏性

- 危险首先通过敌人轮廓、攻击预警、弹道和地面范围表达，HUD 只补充生存状态。
- 构筑差异通过武器形状、弹道、命中特效和升级选择立即可见，不能只体现在属性数字里。
- 波次结束前的节奏变化应由计时、刷怪密度、音效和场景反馈共同建立。

## 塔防

### 玩家任务

观察路径与敌群，判断资源、塔位、射程、升级收益和下一波压力。

### 布局原则

- 路径、入口、出口和可建造区域是保护区。
- 资源、生命和波次组成顶部全局状态条；建造选项放在底部或侧边固定工具带。
- 选中塔后才打开局部检查器，靠近屏幕边缘且不遮挡射程与路径。
- 建造预览、射程和攻击目标必须在世界中表达，不能只写在面板文本里。
- 下一波详情按需展开；战斗中默认只显示敌人类型摘要和开始/加速控制。

## 卡牌战斗 / 构筑

### 玩家任务

比较手牌成本、敌人意图、资源、牌序和状态组合。

### 布局原则

- 手牌占据底部弧形或横向主交互区；悬停/聚焦时向空闲方向放大，不遮挡目标。
- 敌人意图紧邻对应敌人，避免玩家在敌人和远端 HUD 之间反复匹配。
- 能量与结束回合是高频行动，应靠近手牌操作区但保持危险操作隔离。
- 抽牌堆、弃牌堆和消耗堆放在手牌两端，使用数量 + 形状双重编码。
- 复杂词条使用逐层展开：卡面一瞥、聚焦说明、详情百科。

## 平台跳跃 / 动作平台

### 玩家任务

读取角色速度、落点、平台边缘、机关节奏和敌人攻击窗口。

### 布局原则

- 角色前进方向和预期落地区域必须保持干净；不要在屏幕下方铺厚 HUD 遮挡平台。
- 生命/次数放在与主要前进方向相反的上角，收集目标放另一侧。
- 临时交互提示靠近对象但不覆盖落点，完成教学后自动弱化。
- 冲刺、特殊能力等强时机资源可靠近角色或稳定角落，取决于玩家是否需要边移动边精确读取。

## 俯视角动作 RPG / Roguelite

### 玩家任务

瞄准、走位、管理生命/资源、判断技能冷却与小地图信息。

### 布局原则

- 生命与核心资源组成一个强信息簇；技能槽组成第二信息簇，不要散落到四角。
- 小地图默认在上角，透明度和尺寸必须低于战斗威胁；Boss 战或封闭房间可自动简化。
- 冷却使用遮罩 + 数字 + 可用瞬间反馈，但只为玩家能主动触发的技能展示。
- 任务追踪在战斗中自动收起，交互和拾取提示采用上下文出现。

## 解谜

### 玩家任务

理解规则、观察状态、尝试操作、确认因果并追踪目标或步数。

### 布局原则

- 谜题棋盘/机关占据唯一视觉中心，UI 不与可操作元素竞争。
- 目标、步数或时间放在顶部简洁状态区；撤销、重置和提示靠边且避免误触。
- 规则说明逐步揭示，优先使用一次一个事实的上下文提示。
- 正确与错误反馈必须指出因果关系，不只改变颜色或播放通用音效。

## 竞速

### 玩家任务

保持线路、判断速度、弯道、对手、圈数和计时差。

### 布局原则

- 道路消失点和车辆前方是保护区。
- 速度/挡位放在低视线迁移的下角，圈数和计时差放顶部；赛道图保持低对比。
- 位置变化、最佳圈和检查点使用短时强调，不常驻大面积动画。
- 高速时减少文字，使用形状、数字和稳定位置；菜单密度不能沿用到比赛 HUD。

## 恐怖 / 强沉浸

### 玩家任务

感知环境、资源稀缺和不确定危险，同时保持脆弱感。

### 布局原则

- 优先世界内、角色物品或短暂上下文 UI；常驻 HUD 尽量少。
- 隐藏信息必须是有意制造张力，而不是导致玩家无法做合理决策。
- 低血量和危险可通过角色动作、呼吸、声音和画面边缘表达，同时提供可访问的替代提示。
- 背包、地图和日志应符合世界气质，但不能牺牲文字可读性和输入效率。

## 品类组合

混合品类不要把两套 HUD 叠在一起。先判断当前阶段的主玩法，例如“塔防布置阶段”和“动作防守阶段”，分别定义界面状态，再共享生命、资源和视觉 token。
