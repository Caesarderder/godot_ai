# 《Skibidi Toilet：马桶人工厂攻城》游戏 GDD

## 文档状态

这是一份分支级候选 GDD，服务于 `codex/toilet-man-3d-idle` 上的独立游戏方向。它不会替换当前奇幻放置项目的产品不变量或实现事实；在开发者明确选择实现根之前，不修改 `project-a/` 的既有产品定位。

本文区分三种信息：

- **已确认**：开发者在策划会话中明确接受的产品决策。
- **设计假设**：为形成首个可玩版本而提出、仍需试玩验证的可逆参数。
- **待决定**：会实质改变内容范围或实现边界，不能静默代替开发者选择。

## 产品定位

### 已确认

- 题材与世界观：直接使用 `Skibidi Toilet` 的角色、阵营和世界观。
- 发布方式：公开免费的非商业同人游戏，不设置广告、内购或付费内容。
- 首发平台：Web 浏览器。
- 表现形式：横屏 3D 休闲放置游戏，战斗采用自走棋式自动移动、索敌和攻击。
- 核心结构：工厂放置经营与独立自动攻城关卡分离。

原作阵营、故事时期、角色形态和命名边界以 [KM:reference.skibidi-toilet-lore-research](skibidi-toilet-lore-research.md) 为准。当前最重要的剧情约束是：Astro 入侵后 Skibidi 与 Alliance 进入临时合作，因此“持续攻打 Alliance”的主战役应优先取材于停战前的故事时期。

### 发布边界

公开免费不等于获得 IP 授权。发布版本必须：

- 显示清晰的非官方同人声明，不宣称获得原作者或权利方背书；
- 保留替换、撤下争议名称、模型、音频和角色素材的能力；
- 不把未经确认的第三方模型、音乐、音效或商标写入可发布资产清单；
- 在真正公开部署前单独完成素材来源与发布授权审查。

本 GDD 只确认玩法方向，不构成授权结论。

## 玩家承诺与证明时刻

**玩家承诺：** 玩家经营一座持续运转的马桶人工厂，亲手生产、合成和编成稀有 Skibidi Toilet 角色，并在短促夸张的 3D 自动攻城战中通过技能时机扭转局势。

**可观察的证明时刻：** 玩家在一次失败后回到工厂，将三个相同角色永久合成为高星角色，重新编队，再在 Boss 段手动释放该角色的主动技能，突破此前无法摧毁的联盟基地。

## 设计支柱

1. **稀有角色值得拥有**：角色获取有成本，重复角色既能同时上阵，也能作为升星材料。
2. **放置但不旁观**：移动、索敌和普通攻击自动完成，主动技能释放时机由玩家决定。
3. **生产选择可预期**：玩家通过分类车间和指定配方生产目标角色，不使用完全随机抽取作为核心来源。
4. **短局大场面**：每场战斗约一分钟，必须出现清晰的突破、防守升级和最终攻城高潮。
5. **失败推动成长**：失败把玩家送回工厂进行生产、合成和阵容调整，不用重复无意义操作。

## 核心循环

| 步骤 | 玩家意图或输入 | 规则与世界响应 | 关键反馈 | 新状态 |
|---|---|---|---|---|
| 1. 选择配方 | 在分类车间选择要生产的角色 | 检查蓝图、材料和生产槽，满足条件后进入计时队列 | 角色模型预览、材料扣除、倒计时启动 | 生产队列运行 |
| 2. 放置收取 | 在线等待或离线返回 | 完成的配方生成一星角色实例 | 生产线开门、角色登场、稀有度光效 | 角色进入库存 |
| 3. 合成取舍 | 选择三个同角色实例 | 三个实例永久合成一个更高星实例；未合成副本仍可同时上阵 | 三合一动画、体型或装备升级、技能强化提示 | 库存数量减少、单体强度提高 |
| 4. 编成小队 | 选择六个角色并安排战前站位 | 同名角色允许重复；每个位置绑定一个独立角色实例 | 阵容战力、角色职责和技能预览 | 出征阵容锁定 |
| 5. 自动攻城 | 开始关卡 | 六名主力自动移动、索敌、普通攻击；关卡依次进入守军、防御设施、基地或 Boss 三段 | 镜头推进、目标切换、阶段破坏 | 战斗持续推进 |
| 6. 主动施放 | 点击已充能角色技能 | 对应角色独立释放主动技能；部分技能生成临时召唤物 | 头像充能、施法预警、命中与伤害反馈 | 战场局势改变 |
| 7. 结算成长 | 摧毁最终目标或触发失败 | 胜利发放材料和蓝图进度；失败保留既有角色并返回工厂 | 胜负原因、关键贡献、下一步建议 | 新一轮生产或重试 |

### 首个可玩前 30 秒

**设计假设：**

1. 玩家进入正在运转但尚未扩建的工厂，普通车间点亮，其余三个车间以可预览的锁定状态出现；
2. 界面直接赠予第一份普通配方所需材料，并把“选择配方”作为唯一主目标；
3. 玩家选择一个基础 Skibidi Toilet 配方，首个教学订单压缩为约 5 秒；
4. 生产线开门并展示第一个永久角色，库存显示 `1 / 6`，下一目标明确指向“完成第一支出征小队”；
5. 这段教学不自动替玩家选择后续配方，不自动合成，也不制造付费或随机抽取预期。

## 工厂与生产

### 分类车间

| 车间 | 已确认职责 | 典型角色定位 |
|---|---|---|
| 普通车间 | 低成本、较短周期的基础配方 | 基础近战、基础远程、低费前排 |
| 飞行车间 | 生产可越过地面阻挡的角色 | 空中突袭、后排压制 |
| 重装车间 | 生产大型、耐久或攻城角色 | 承伤、破坏设施、推进 |
| 特殊车间 | 生产拥有控制、召唤或特殊机制的角色 | 寄生、控制、辅助、标志性角色 |

### 材料结构

已确认采用三种共享材料与角色专属蓝图：

- 陶瓷组件；
- 机械零件；
- 污水能源；
- 角色专属蓝图。

不同配方通过材料比例、蓝图要求和生产时间体现差异。材料不为每个角色新增独立背包品类。

### 离线生产

**设计假设：** 已加入队列的配方在离线期间继续计时；离线不会自动选择新配方、自动消耗新材料或自动合成角色。离线结算上限和生产槽数量待试玩后确定。

## 角色、稀有度与合成

### 固定稀有度

| 稀有度 | 强度与机制定位 | 获取预期 |
|---|---|---|
| 普通 | 基础属性和清晰单一职责 | 配方成本最低、最容易升星 |
| 稀有 | 更高属性并具备明确战术优势 | 需要更多材料或蓝图 |
| 史诗 | 主动技能可明显改变局部战局 | 较长生产周期、蓝图更少见 |
| 传说 | 标志性角色或形态，拥有强力主动技能 | 长周期、高成本、稀有蓝图 |

- 每个角色拥有固定稀有度，不随机生成品质。
- 同一角色的不同进化形态作为独立角色和独立配方，例如不同阶段的 G-Toilet。
- 稀有度决定基础强度、技能上限和生产成本；星级决定同一角色实例的成长程度。

### 永久合成

已确认规则：

```text
3 个同角色、同星级实例 → 1 个下一星级实例
```

- 合成只发生在工厂，不在战斗中临时合成。
- 同名角色允许重复上阵，最多可占满六个编队位置。
- 每个上阵实例独立拥有生命、能量和技能状态。
- 玩家必须在“保留多个低星角色形成数量优势”和“合成更少的高星角色形成质量优势”之间选择。
- 关键星级应强化或改变技能表现，避免升星只做无感的线性数值增长。

## 战斗契约

### 阵容与自动行为

- 每场使用六名永久主力角色。
- 战前选择角色和站位；开战后不手动控制移动和普通攻击。
- 角色根据职责、攻击距离和目标规则自动移动、索敌和攻击。
- 主力全部阵亡或计时耗尽时失败；临时召唤物阵亡不计入失败条件。
- 战斗中不生产永久角色，也不进行永久合成。

**设计假设：** 首个可玩版本采用前后两排、每排三个位置的战前站位；角色离开出生位置后由自动战斗逻辑接管。该布局尚未获得最终确认。

### 主动技能

- 每个角色至少拥有基础属性、自动攻击、被动或特性，以及一个可由玩家选择时机释放的主动技能。
- 每个角色实例独立积攒技能能量。
- 头像显示能量状态并作为技能按钮；未满足条件时不能释放。
- 一部分角色技能可以召唤临时马桶杂兵、寄生单位或自爆单位。
- 临时单位只存在于当前战斗，不进入库存、合成或永久养成。

### 三段式攻城

```text
第一段联盟守军
→ 第二段防御设施或精英单位
→ 第三段联盟基地或 Boss
```

- **成功：** 在时间耗尽前摧毁最终基地或击败 Boss。
- **失败：** 六名主力全部阵亡，或关卡计时耗尽。
- **恢复：** 回到工厂，保留永久角色和已完成成长，重新生产、合成或调整阵容。
- **重试：** 玩家重新确认阵容后从关卡初始状态开始，不继承上次战斗的生命、能量和临时召唤物。

## 关键反馈契约

| 关键事件 | 最低反馈要求 |
|---|---|
| 配方开始 | 材料飞入设备、生产线启动、剩余时间清晰可见 |
| 生产完成 | 车间开门、角色完整亮相、名称与稀有度同时出现 |
| 三合一升星 | 三个实例汇聚、轮廓或装备升级、属性与技能变化可比较 |
| 技能就绪 | 角色头像充能完成、短音效和轻量脉冲，不遮挡战场 |
| 技能释放 | 施法者、目标区域和结果在同一战斗节拍内可辨认 |
| 阶段突破 | 防线被破坏、镜头向前推进、下一目标明确出现 |
| 胜利 | 最终目标发生夸张破坏，奖励来源与下一步成长路径清楚 |
| 失败 | 明确区分全灭和超时，并提示阵容、星级或技能时机中的一个可行动方向 |

## 首个可玩内容切片

### 必须证明

1. 一条指定配方生产完整流程；
2. 三个同角色永久合成一次；
3. 六人阵容允许至少两个同名角色同时上阵；
4. 一场包含三段目标的自动攻城；
5. 至少两个角色拥有可主动释放、效果不同的技能；
6. 至少一个技能生成临时召唤物；
7. 一次失败回厂成长后再胜的闭环；
8. Web 浏览器中鼠标和触屏均可完成核心操作。

### 设计假设

- 首个切片准备 8 个可生产角色，让六人阵容存在至少两种替换选择。
- 四类车间各至少展示一个配方，其余配方可以锁定预览。
- 首个切片包含 3 个关卡：教学防线、精英设施、章节 Boss。
- 单局目标时长为 45–60 秒。

### 明确暂不做

- 商业化、广告、内购和付费抽取；
- PvP、排行榜、公会、玩家交易和联机协作；
- 连续开放世界或无缝城市扩张；
- 战斗内购买角色或临时三合一；
- 手动控制角色移动和普通攻击；
- 完整复述原作所有章节与角色；
- 未经素材审查的公开部署。

## 数值与调优契约

| 值 | 初始范围或关系 | 预期玩家效果 | 调整证据 |
|---|---|---|---|
| 编队人数 | 已确认 6 名 | 允许角色组合与重复角色取舍，同时保留技能可管理性 | 玩家频繁误触或无法关注多个技能时再缩减 |
| 合成需求 | 已确认 3 合 1 | 让副本保留和升星之间形成真实选择 | 玩家总是无脑合成或永不合成时调整生产成本和星级收益 |
| 关卡结构 | 已确认 3 段 | 每局形成建立、升级和高潮 | 玩家无法辨认阶段变化时加强目标和镜头反馈 |
| 单局时长 | 假设 45–60 秒 | 适合浏览器短会话，并允许至少一次技能决策 | 大多数测试者在中段前离开或技能尚未就绪时调整 |
| 材料种类 | 已确认 3 种共享材料加蓝图 | 保留配方差异，不让背包认知过载 | 测试者无法解释材料用途时合并材料 |
| 稀有度 | 已确认 4 档 | 快速表达强度、成本和期待值 | 低稀有角色完全失去使用率时强化低稀有升星效率 |

## 验收与试玩证据

| 行为或假设 | 确定性检查 | 真人观察 | 通过信号 |
|---|---|---|---|
| 指定生产 | 材料足够时只有玩家选择的配方进入队列，材料不足时不扣除任何材料 | 新玩家能说出正在生产哪个角色及剩余时间 | 无需说明即可完成首次生产 |
| 永久合成 | 只有三个同角色、同星级实例能够生成一个下一星级实例 | 玩家会在保留三份和升星之间犹豫 | 至少一种关卡使两种选择都可解释 |
| 重复上阵 | 两个以上同角色实例可以同时进入六人阵容并独立战斗 | 玩家理解它们是独立实例而非显示重复 | 能分别观察到生命、能量和技能状态 |
| 自动攻城 | 开战后不输入移动指令也能依次进入三段目标 | 玩家能在十秒内指出当前目标 | 不需读实现说明即可理解推进方向 |
| 主动技能 | 能量未满时不可释放，充满后点击只触发对应实例一次 | 玩家会为精英段或 Boss 段保留至少一次技能 | 玩家能描述一次“因为释放时机而赢”的瞬间 |
| 临时召唤 | 召唤物不进入永久库存，战斗结束后全部清理 | 玩家享受军团规模突然扩大的场面 | 不会误以为召唤物可以带回工厂 |
| 失败恢复 | 全灭或超时后停止战斗写入，回厂后永久成长仍保留 | 玩家失败后主动生产、合成或换阵，而非直接退出 | 至少一名新玩家完成失败后成长再胜 |
| Web 输入 | 鼠标与触屏均可完成生产、合成、编队和施法 | 玩家不需要精确点击移动中的 3D 单位 | 关键操作只依赖稳定 UI 目标 |

## 概念性 Godot 边界

本节只约束所有权和数据流，不决定最终场景树或类名。

| 所有者 | 负责 | 不负责 |
|---|---|---|
| 工厂持久状态 | 材料、蓝图、生产队列、角色实例、星级 | 当前战斗生命、能量和召唤物 |
| 编队状态 | 六个出征槽和战前站位 | 自动索敌与即时战斗结果 |
| 关卡定义 | 三段目标、敌人配置、时间限制、奖励表 | 玩家永久库存 |
| 战斗运行状态 | 主力战斗副本、生命、能量、目标、临时召唤物和胜负 | 永久合成与离线生产 |
| 结算边界 | 将已确认的胜负与奖励一次性写回持久状态 | 在战斗过程中直接改写工厂库存 |

关键数据流：

```text
工厂持久状态
→ 生成只读出征快照
→ 战斗运行状态自动推进
→ 玩家触发某个角色实例的主动技能
→ 胜负结算
→ 奖励一次性写回工厂持久状态
```

Web 实现必须验证：

- 3D 战斗在目标浏览器和手机浏览器中的帧率、首包体积与内存；
- 页面失焦、切后台、刷新和断线时生产计时与战斗状态的处理；
- 鼠标与触控共享同一套确定性操作语义；
- 临时召唤物和重复角色不会在重试、切场景或刷新后残留。

## 待决定

1. 玩家是否永久只培养 Skibidi Toilet 阵营，联盟角色是否永远只作为敌人；
2. 首个切片的具体八名角色、固定稀有度、配方与技能；
3. 六人阵容是否最终采用 `2 × 3` 固定站位；
4. 技能能量的来源、共享或独立规则、起始值与释放限制；
5. 离线生产上限、生产槽数量和是否允许队列扩展；
6. 第一章使用哪一类联盟敌军和哪个标志性 Boss；
7. Godot 新游戏的独立实现根与现有 `project-a/` 的关系；
