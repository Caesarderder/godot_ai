# 游戏状态度量与数值换算框架

## 目标

建立制作人、策划、程序、测试和后续商业化共同使用的数值语言，用有限的一组单位解释：

- 玩家当前能稳定推进到哪一关，为什么卡住；
- 一次角色或设施升级带来多少真实推进价值；
- 四种核心资源与玩家时间如何比较；
- 工厂能支持多少次连续攻城，以及间接带来多少金币获取能力；
- 当前经济是否出现通胀、资源废弃、死锁或内容消耗过快；
- 未来礼包、订阅、加速和补给如何定价而不破坏非付费闭环。

本框架是**策划测量合同**，不是“已经平衡”的声明。任何数字必须带证据标签。

## 证据标签

| 标签 | 含义 | 可用于什么 | 不能证明什么 |
|---|---|---|---|
| `implemented` | 当前代码或配置中的真实值 | 复现当前行为、发现结构问题 | 好玩、公平、商业价值 |
| `derived` | 从 implemented 值确定性计算 | 换算、比较、敏感性分析 | 玩家真实决策 |
| `target` | 已接受的设计护栏 | 新内容预算、验收 | 当前实现已经满足 |
| `playtest hypothesis` | 等待真人验证的区间 | 试玩问题、实验设计 | 玩家已经认可 |
| `measured` | 来自明确版本、样本和口径的记录 | 校准模型 | 其他版本或人群仍成立 |
| `unknown` | 尚无可靠证据 | 暴露缺口 | 不得填入“行业惯例”伪装精度 |

表格、看板和评审结论必须显示标签。没有版本号、样本、时间窗和事件定义的数据不能标为
`measured`。

## 一、基础单位

### 1. 工业材料分钟 IM（Industrial Material Minute）

所有资源产线汇入同一工业材料库存；每条 L1 产线基准产速为 `3/分钟`。对工业成本 `C`：

```text
当前总产速 P = Σ(每条已建产线的等级 × 3 × 派驻倍率)
等待时间 TFA(C) = max(0, C - 当前库存) / P
工业负载 IL(C) = C / 3
```

- `TFA` 回答当前库存不足时还需等待多久；
- `IL` 把配方换算成一条 L1 产线需要运行的分钟数；
- 新档 `112` 与建造成本由旧三材料按生产时间归一化：
  `round((2×陶瓷 + 4×零件 + 3×能源)/4)`；
- 该折算只用于 schema v8→v9 一次迁移，不开放为玩家可反复套利的兑换。

例：研究所成本 `30` 工业材料，等于 `10 IL`；新档支付后从 `112` 降为 `82`。

### 2. 战争分钟 WM（War Minute）

金币、军团数据、招募券和经验没有无条件工厂来源，不得强行按 IM 直接兑换。定义：

```text
单次战役周期 = 战斗时间 + 菜单决策时间 + 必要维修等待时间
WM = 一分钟真实主动战役周期
```

对资源 `r`：

```text
战争获取速率 WAR_r =
Σ(关卡选择概率 × 胜率 × 奖励_r) / 平均战役周期分钟
```

没有真人数据时，关卡选择概率和胜率必须标为 `unknown`；可以使用确定性模拟分别输出
胜利场景、失败场景和上下界，但不能伪称真实平均值。

### 3. 可见成长事件 MGE（Meaningful Growth Event）

一次 MGE 必须至少满足一项：

- 让原本“高风险”的城镇进入“目标区间”；
- 解锁技能、被动、派驻或维修槽等新选择；
- 将一次常规战损的恢复时间降低至少一个可感知档位；
- 使瓶颈资源、容量或离线窗口发生玩家能复述的变化；
- 改变推荐阵容或战后策略，而非只增加不可察觉的小数值。

首局目标：每 2–3 场至少出现一次 MGE。标签：`target`。

## 二、战力与关卡换算

### 1. 战力不是资产总分

当前无损合同维护两个运行时战力；旧 `CP_full/CP_ready` 字段只作兼容展示并且数值相等：

| 指标 | 定义 | 用途 |
|---|---|---|
| 编队战力 `CP_formation` | 当前上阵角色按唯一 `CombatPower` 公式相加 | 长期养成与战前推荐 |
| 对关有效战力 `CP_stage` | 在编队战力上计入关卡机制、职责覆盖和克制 | 预测具体关卡 |

不得用账号所有角色战力之和或页面私有公式预测关卡；不得把未上阵或不适配机制的能力计入。

### 2. 单角色基础能力

当前唯一展示战力由 `CombatPower.stats_power` 实现：

```text
CP_i =
  hp × 3
  attack × 20
  defense × 10
  speed_milli / 500
  crit_bp / 10
```

- 该公式为 `implemented`，所有 UI、成长预览和能力比必须调用同一实现；
- 星级只在角色派生属性中把生命、攻击、防御按 1★/2★/3★ 的
  `1.00/1.30/1.60` 计算一次；速度、暴击不乘星，战斗快照和 `CombatPower` 不得再次乘星；
- 职责、主动技能等级不进入展示战力；等级、升星的效率分别报告成本与 `ΔCP`，技能价值必须由
  真实战斗机制与固定 seed 扫描衡量，不能用隐藏加分替代。

### 3. 无损状态换算

当前战斗结算后所有永久角色恢复为 100% 可出征：

```text
CP_formation = Σ CP_i（仅当前编队）
兼容字段 CP_full = CP_ready = CP_formation
```

`readiness`、`injury_flags` 和维修订单仅作旧存档迁移输入，不得改变当前战力、限制出征、生成成长建议或消耗资源。

### 4. 阵容协同与职责覆盖

```text
CP_stage = CP_formation × Synergy × Counter_stage × Coverage_stage
```

护栏：

- `Synergy` 首轮限制在 `0.90–1.15`，避免组合乘区导致指数膨胀；
- `Counter_stage` 首轮限制在 `0.85–1.15`，克制应改变选择但不使养成失效；
- `Coverage_stage` 反映是否具备前排、对结构、远程/范围与维修支持；
- 所有乘区总乘积必须设版本级上下限，不允许每加一个系统再新增独立乘区。

标签：`target`。

### 5. 关卡需求与能力比

关卡推荐战力不能由敌人面板简单求和。正确做法是：

1. 固定一组代表性阵容与 seed；
2. 在同一关卡进行确定性强度扫描；
3. 找到目标胜利、通关时间和伤损区间的最低 `CP_stage`；
4. 将其定义为该关 `Demand_stage`；
5. 真人试玩再校准“可理解、可接受、愿意重试”。

```text
能力比 CR = CP_formation / Demand_stage
```

首轮风险显示假设：

| CR | 预测标签 | 策划含义 |
|---:|---|---|
| `< 0.80` | 极高风险 | 非克制或高手策略下大概率失败 |
| `0.80–0.94` | 挑战 | 可尝试，但可能失败或需要调整阵容 |
| `0.95–1.09` | 目标区间 | 应形成有压力但可理解的推进 |
| `1.10–1.29` | 稳定 | 常规胜利 |
| `≥ 1.30` | 碾压 | 关卡主要承担复习或回收价值 |

标签：`playtest hypothesis`。

### 6. 玩家“能打到第几关”

必须分别输出战斗上限与经济可达性：

```text
战斗可通关 = 最大 stage，使 P(win | 当前阵容, seed 集) 达到挑战阈值
经济可达关卡 = 从指定新档状态按真实奖励、工厂产出和成长成本执行合法策略后，
  能在目标时间预算内达到挑战线或推荐线的最大 stage
```

预制毕业阵容通关只能证明战斗内容骨架，不证明经济可达；必须另跑从新档开始的确定性经济推进扫描。

五项模型下首章前三关入口推荐战力统一为 `1650`，1-4 为 `5000`，1-5 为 `5400`。
2026-07-27 的 7-seed、77 场确定性扫描得到：新档 Gman 战力 `1603–1683` 且前三关全胜；
三人基础编队战力 `4924–5055`，1-4 全胜而 1-5 全败；把冲锋或装甲升至二星后，两条路线均
7-seed 全胜并落入 `420–499 tick`。二星倍率由 `1.25` 最小上调至 `1.30`，三星相应为
`1.60`，没有修改敌人数值或技能。标签：推荐线、胜负与时长为
`implemented / derived deterministic scan`，真人压力感和选择质量为 `playtest hypothesis / unknown`。

首章后不再使用单调小步递增的线性关卡表。根据玩家对“三关一墙”过密的反馈，当前第二章起采用
“4–5 关推进窗 → 章节 Boss 成长墙”的宽松锯齿包络：首轮保守账本把三人编队的可显示战力消费到
`9172–9554`，固定 7 seed 均通过 2-1/2-2/2-3/2-4，并在 2-5 全败；领取四关保守首通战果并
再次消费到无法继续成长后，编队战力达到 `10961–11558`，固定 7 seed 均通过
2-5/3-1/3-2/3-3/3-4，并在 3-5 全败。对应推荐线为
`6900/7300/7700/8100/9000/9400/9800/10200/10600/11500`。后续显式墙只保留
2-5/3-5/4-5/5-5；普通关步进为 400，Boss 跳幅为 900。第二章起的章节 Boss 使用显式关卡参数
调整核心炮压，并仅在编队低于“推荐战力 + 1000”时启动 85 tick 核心过载；未配置关卡继续使用
46 伤害、42 tick 的旧巨炮参数，首章 1-5 不受影响。敌方原始倍率允许因 Boss 额外结构和巨炮模板
而回落，必须由真实战斗结果而不是倍率单调性证明需求递增。标签：前两个周期为
`implemented / derived deterministic scan`；后续周期仍为 `target`，真人节奏感为 `unknown`。

同一推进扫描现在把 1-5 后的新游福利纳入真实路径：先 exact-once 领取“黑金升星核心”和
“走私后勤箱”，开启后勤箱获得 `25` 工业材料，再用核心完成一次 1★→2★ 升星。
核心免除该次 `4` 军团数据。福利路径下首轮
为 `9172–9554`、第二轮为 `10961–11558`，两轮资源消费后都不存在可负担的永久成长项，
2-5 与 3-5 两堵章节 Boss 墙保持不变。标签：物品唯一性、原子存档与确定性节奏为 `implemented / measured`；
玩家是否产生“走捷径/开挂”的主观感受以及是否因此继续游玩为 `playtest hypothesis / unknown`。

首章战斗压力另使用 7 个新档固定 seed 校准体验台阶：1-1 无伤教学，1-2 只承受轻微远程伤害，
1-3 单人 Gman 稳定胜利但剩余生命为 `1%–19.5%`，1-4 单人 Gman 在三人通关基准时长的
`40%–65%` 区间内阵亡。受击充能按实际生命损失占最大生命百分比结算，单次最多 10、每秒最多
20；它通过真实战斗扫描反映到关卡需求，不作为页面私有加分直接叠入 `CombatPower`。
标签：`implemented / derived`。

## 三、四资源与成长换算

### 1. 不建立全局固定汇率

金币、军团数据、工业材料和招募券承担不同门禁。固定写成
“1 金币 = N 工业材料”会造成以下错误：

- 忽略产线数量、派驻和当前库存；
- 忽略金币只能从主动战果获得；
- 让礼包可以绕过原本独立的玩法门禁；
- 在版本新增消耗后立即失真。

使用三种局部影子价格：

| 影子价格 | 算法 | 回答的问题 |
|---|---|---|
| 时间价格 | `TFA` / `IL` | 需要等多久、占多少工业负载 |
| 成长价格 | 成本 ÷ 获得的 `ΔCP` 或 MGE | 哪个升级更有效 |
| 推进价格 | 成本 ÷ `ΔCR` 或新增可持续关数 | 哪笔投入最能解卡 |

### 2. 升级效率

对升级 `u`：

```text
角色成长效率 = ΔCP_formation / (金币成本, 军团数据成本)
设施成长效率 = 新产速或新能力 / (工业材料成本, TFA)
Progress Efficiency_u = Δ经济可达关数 / 总等待时间
```

不得为了生成单一排行榜而把金币、军团数据和工业材料强行相加。比较同一成长域时使用同维度成本；
跨域选择同时报告资源向量、TFA、`ΔCP`/新能力和机会成本。

### 3. 资源压力向量

对未来规划窗 `H`（默认下 3 个 MGE）：

```text
Pressure_r = 预计需求_r / (当前库存_r + H 内预计来源_r)
```

| Pressure | 状态 |
|---:|---|
| `< 0.7` | 富余 |
| `0.7–1.0` | 健康 |
| `1.0–1.3` | 紧张 |
| `> 1.3` | 瓶颈 |

标签：阈值为 `playtest hypothesis`。工厂首页的“当前瓶颈”必须来自压力向量，而不是只找余额最少的
资源。

### 4. 资源用途覆盖率

```text
Utility Coverage_r =
当前章节中具有真实决策价值的消耗项数量 / 当前章节全部关键消耗项数量
```

若一种资源连续一个章节没有至少两个互斥或有优先级的用途，则它更像领取噪音而非策略资源。
资源越多，商业礼包越难解释，因此新增货币前必须证明它有独立门禁和独立决策。

### 5. 金币不是工厂直接产物

当前产品合同下：

```text
工厂直接金币产速 = 0
```

应衡量的是**工厂支持的金币获取能力**：

```text
可支持出征数/day =
min(
  工业材料日产量 / 单次期望工业材料净消耗,
  玩家可用战役时间 / 单次战役周期
)

间接金币能力/day =
可支持出征数/day × 加权胜率 × 单次有效金币奖励
```

“单次净消耗”必须扣除战役可能返还的工业材料。若战役稳定返还多于维修消耗，会形成越打资源越多的
正反馈；此时应把材料奖励视为首通补给或设可控衰减，而不是宣称工厂效率提高。

## 四、无损连续作战与成长可达

战斗失败不会损失永久战力，因此连续重试没有维修门槛。当前需要测量的是下一成长可达时间：

```text
Growth ETA =
从当前库存、产速和可重复战果出发，
执行一个能产生正向 ΔCP 或新机制节点的合法成长所需时间
```

不变量：

- 失败不能降低账号状态或创建恢复债务；
- 下一成长不能要求付费、广告或每日刷新；
- 工业资源为零时仍能通过受控离线生产重新获得成长选择；
- 战斗金币不足时必须存在可理解的可重复战果路径；
- 首局与回流分别记录 Growth ETA，不能用预制毕业阵容替代经济可达性。

## 五、工厂状态指标

工厂状态不得只显示库存。策划看板至少包含：

| 指标 | 公式/定义 | 诊断 |
|---|---|---|
| 有效产速 `P_eff` | 基础产速 × 等级 × 派驻 × 增益 | 当前真实能力 |
| 存满时间 | 剩余容量 / `P_eff` | 离线损失风险 |
| 领取损失率 | 溢出产量 / 理论产量 | 容量是否制造焦虑 |
| 瓶颈资源 | 未来 3 MGE 的最高 `Pressure_r` | 下一扩建设施 |
| 产能利用率 | 实际被消耗资源 / 可生产资源 | 是否有无用产能 |
| 成长占比 | 升级/研究 IL / 总 IL | 玩家是否在前进 |
| 下一 MGE ETA | 达成最优可执行成长的时间 | 玩家下一目标 |

健康假设：

- 领取损失率长期高于 10% 时，容量更像惩罚而非策略；
- 单一资源连续两个规划窗 `Pressure > 1.3`，应检查配方或产速，而不是立刻销售该资源；
- 工业材料长期富余说明设施消耗不足，不能靠恢复多材料分账制造伪瓶颈。

以上为 `playtest hypothesis`。

## 六、玩家状态仪表盘

### 1. 单玩家快照

每次策划复盘按同一格式记录：

| 维度 | 必填字段 |
|---|---|
| 进度 | 当前关、最高通关、可持续关、挑战关、章节时间 |
| 军团 | `CP_full`、`CP_ready`、职责覆盖、平均/最低战备 |
| 后勤 | 三库存、三产速、压力向量、续航、存满时间 |
| 恢复 | 当前维修缺口、RB、DRT、失能角色数 |
| 成长 | 下一 MGE、ETA、升级效率、最近 3 次成长类型 |
| 战役 | 最近胜败撤退、通关时间、伤损、净奖励 |
| 目标 | 当前主目标、次目标、是否知道下一行动 |

由此输出五个解释性结论：

1. **当前瓶颈**：战力、机制覆盖、战备、工业资源、金币、技术或理解；
2. **预计可持续推进**：关卡编号与置信标签；
3. **最快解卡动作**：一个主建议，不列十个等价升级；
4. **无操作恢复时间**：多久能重新做出有意义选择；
5. **当前经济风险**：通胀、死锁、单币垄断、资源废弃或内容消耗过快。

### 2. 版本健康看板

| 指标 | 目的 |
|---|---|
| 首次 MGE 时间 | 判断开局是否空转 |
| 每 MGE 间隔 | 发现成长死区和过密奖励 |
| 关卡 CR 分布 | 发现难度断层 |
| 胜利后 RB 分布 | 判断维修是否为策略或税 |
| 失败后 DRT | 判断是否死锁或惩罚过重 |
| 资源 Pressure 分布 | 找经济瓶颈与废币 |
| 资源来源/消耗比 | 找通胀和永久亏空 |
| 首通净资产变化 | 判断战斗是否自我增殖 |
| 章节内容消耗时间 | 预测内容寿命 |
| 建议动作采纳率 | 判断推荐是否可信 |

没有遥测时用确定性玩家状态样本输出上下界；不得制造留存率或付费率。

### 3. 内容寿命

```text
Content Runway =
剩余 MGE 数量 × 中位 MGE 间隔
```

同时报告：

- 主线首通时长；
- 全功能理解时长；
- 全角色/设施数值毕业时长；
- 每周可重复但不强制的决策量；
- 内容生产成本与玩家消耗速度之比。

只增加 HP 和攻击延长时长，不算增加内容寿命；至少需要新机制、阵容选择或后勤决策。

## 七、数值膨胀护栏

### 1. 单一增长预算

每章节先确定总推进预算，再分配给系统：

```text
章节总能力倍率 =
等级倍率 × 星级倍率 × 技能倍率 × 阵容倍率 × 工厂支持倍率
```

不允许各系统各自决定“每章翻倍”。首轮建议：

- 普通关推荐需求相邻增长平滑；
- Boss 可以形成台阶，但台阶必须对应已教学的新机制或 MGE；
- 单个新系统的常驻乘区不超过 `1.15`，除非它替代旧乘区；
- 总乘区设硬上限，优先使用加法、能力解锁和情境价值；
- 伤害、生命、金币和成本使用整数与集中配置，禁止 UI 自己换算。

标签：`target`。

### 2. 显示尺度

- 首章战力建议保持 3–5 位有效显示，不为“爽感”主动加零；
- 资源显示保留玩家能比较一次升级成本的粒度；
- 只有真实值超过 9999 后才使用 K/M 缩写；
- 缩写只影响显示，存档和计算继续使用整数；
- 不使用多个名称表示同一价值层，如金币/马桶币/现金并存。

### 3. 通胀指数

对资源 `r`，以章节或版本为窗：

```text
Inflation_r =
中位来源速率增长 / 中位有意义消耗成本增长
```

- 持续 `> 1`：库存膨胀，消耗失去意义；
- 持续 `< 1`：购买力下降，容易形成硬墙；
- 必须同时看库存分布和用途覆盖，不能仅靠同步抬高全部价格“解决通胀”。

## 八、商业化前置度量

本节只定义未来评估语言，不批准真实支付、广告或概率抽取。商业上线仍受 IP 授权、支付、
隐私、退款和未成年人保护门禁约束。

### 1. 非付费基线先成立

任何商品设计前必须证明：

- 非付费 DRT 合理且无死锁；
- 非付费玩家可以完成主线，不需要购买独占战力；
- 工厂容量不是人为制造的高频惩罚；
- 失败原因可理解，付费不会替代学习；
- 商品解决的是偏好、节奏或表达，不是修复故意制造的坏体验。

### 2. 商品统一价值单位

商品不得只按原始资源数量比较。拆为：

| 价值维度 | 建议单位 |
|---|---|
| 后勤价值 | 节省的 `TFA` 与 `IL` |
| 战争价值 | 节省的 WM 或增加的可选战役次数 |
| 成长价值 | 提前多少个 MGE |
| 推进价值 | 增加多少 `ΔCR` 或可持续关数 |
| 便利价值 | 减少多少重复操作，不改变胜负权威 |
| 表达价值 | 外观、收藏、叙事，不计入战力 |

所有礼包都要展示“对非付费时间线的影响”，避免多个币种隐藏真实价格。

### 3. 商业化风险指标

| 指标 | 风险信号 |
|---|---|
| 付费推进差 `Paid Progress Gap` | 付费直接跨过未理解机制或连续多个 MGE |
| 付费恢复优势 | 付费使伤损系统失去选择，永远无成本满修 |
| 商品垄断率 | 某资源的主要来源变为付费而非玩法 |
| 价格不透明度 | 同一价值被多币种、限时和随机概率遮蔽 |
| 失败付费触发率 | 商品只在失败/重伤时高压弹出 |
| 非付费内容可达率 | 非付费无法合理到达核心章节或角色机制 |
| 购买后内容坍缩 | 购买使剩余内容寿命大幅缩短 |

商业化评审必须同时查看收入假设、玩家选择质量和内容寿命；不能只提高短期转化。

### 4. 推荐的低风险顺序

在获得商业权限且非付费闭环验证后，优先评估：

1. 纯外观与收藏表达；
2. 不改变战斗结果的便利功能；
3. 有上限、透明、不会跳过机制学习的节奏加速；
4. 明确内容包；
5. 最后才评估随机获取，并单独处理概率、保底、重复物和未成年人规则。

这是产品风险顺序，不是实现批准。

## 九、内容与数值评审流程

新增关卡、角色、设施、资源或商品前，必须填写：

1. 玩家行为目标与新选择；
2. 可用时间点；
3. 成本向量、来源、库存和门禁；
4. `ΔCP_full`、`ΔCP_stage` 或 MGE；
5. 对 CR、RB、DRT、Pressure、Content Runway 的影响；
6. 是否新增乘区、货币或稳定正反馈；
7. 一个主变量实验，其他控制项保持不变；
8. 自动验证和真人观察分别是什么；
9. 失败时的回滚值；
10. 证据标签。

停止条件：

- 无法说明玩家获得什么新选择；
- 只能用“数值更大”解释价值；
- 需要新增货币才能掩盖旧币失衡；
- 商品先于非付费闭环成立；
- 预测依赖未知胜率却写成确定结论；
- 新关卡需求台阶没有对应教学、机制或成长事件。
